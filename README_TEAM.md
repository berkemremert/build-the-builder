# Team runbook

This runbook supplements the official [kit README](README.md). The brief and its
matching OpenAPI file are the source of truth for each run. The builder must read
both files and create the Freya phone agent without a manual workflow edit.

## Reproduce a build

From `build-the-builder/`, with Python 3.10 or newer and the local credentials
described below, run the builder with a brief and its matching tool schema:

```bash
python3 builder.py --brief {brief_path} --openapi {tool_api_path} --slot {slot_name} --out {output_dir}
```

In live mode, the command saves and publishes a workflow, exports the resulting
workflow JSON, and writes a trace. Keep the printed workflow ID, agent ID,
export path, and trace path together. `--brief` may be repeated. For public Brief B, pass both
`--brief briefs/brief-a.md --brief briefs/brief-b.md` in that order; B amends A
and is not a standalone policy. `--no-live` builds local artifacts without a
Freya call and is useful for offline checks; its workflow file is **not** a
Freya export for final submission.

Run the offline acceptance suite before using the Freya workspace:

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

When credentials are available, validate a public agent with the official runner
from this directory. One workspace simulation runs at a time:

```bash
python3 tools/run_cases.py <agent_id> --brief A --reps 3 --out results/public-a.json
python3 tools/run_cases.py <agent_id> --brief B --reps 3 --out results/public-b.json
```

The runner's score combines bank ledger state, policy, and honesty. One successful
repetition is not proof of reliability; the final evaluation requires all three
repetitions of a case to pass. `--style pieces`, `corrects`, `talkative`,
`asks_back`, and `in_words` exercise more natural phrasing.

## Credentials and local files

Create a Freya workspace API key and a stable synthetic bank team key of at least
16 characters. Set them in your shell from a local file outside the repository,
or fill in a local `env.sh` copied from `env.example` and keep it untracked:

```bash
cp env.example env.sh
# Edit env.sh locally, then:
source env.sh
```

`FREYA_API_KEY` is the workspace credential. `FREYA_BANK_TEAM_KEY` isolates the
practice bank ledger. `FREYA_API_URL` normally uses the kit's staging default.
`OPENAI_API_KEY` is required for the production builder to compile a policy.
The builder sends the supplied briefs and complete OpenAPI file directly to
OpenAI's `gpt-6-sol` Responses API, then validates the returned policy with
`compile_policy`. The request uses medium reasoning, JSON object output,
`store=false`, and a 25,000-token output allowance. It has a 900-second request
timeout within the 30-minute total build limit. The command does not require a
Claude or Codex CLI login.
The trace records both the requested and serving model IDs.
If the key is missing, the model response is incomplete, or the policy fails
validation, the build fails and records the reason in its trace; it does not
publish a source-only fallback.
Never paste a key into a brief, prompt, workflow export,
trace, screenshot, commit, or submission. Inspect generated artifacts for secrets
before committing. Keep local state such as `.freya-agents.json`, persona caches,
and `env.sh` out of the commit.

## Submission checklist

- [ ] Both agents were generated by the submitted builder commit from the two
  hidden briefs and their respective OpenAPI files, with no manual agent edits.
- [ ] The two workflow exports were obtained with
  `freya.export_workflow(workflow_id, path)` and are the versions chosen for
  submission. Their workflow and agent IDs match the traces.
- [ ] One trace per brief records start and end times, every builder model call's
  model and one-line purpose, Freya workflow and agent IDs, node and tool counts,
  and each self-test with its result.
- [ ] The repository commit includes builder code, both exports, and both traces;
  the exact commit hash and repository URL are recorded.
- [ ] The Git repository and remote are available at submission time. Copy
  chosen exports and traces from the ignored local `out/` directory to a
  deliberate `submission/` path before committing.
- [ ] The submission includes team identity, repository URL, exact commit,
  reproducible command with `{brief_path}` and `{tool_api_path}`, two export
  paths, and two trace paths.
- [ ] No API keys or other credentials are present in committed files or
  submitted artifacts.
- [ ] Submission is sent before 23:00 Istanbul time on Sunday, 11 October 2026.

The final briefs may change identity questions, limits, outcome codes, calendars,
request fields, and allowed enum values. Read these from the inputs on every run.
Use the call's `now` variable for dates; the host clock is not the caller's date.
